# Orbit Server Management Panel — Threat Model Report

## Overview

- **Application**: Orbit (Go 1.22 + React/Vite + SQLite + BoltDB)
- **Repository**: github.com/KenyanRedwoods01/Orbit
- **Purpose**: Server management panel — SSH terminal, Docker management, file browser, cron, backups, Wazuh SIEM, CI pipelines, agent protocol, firewall, reverse proxy, database admin
- **Scope**: Full-stack web application with OS-level access, Docker socket mounted (read-only), manages SSH keys and remote servers
- **Report Updated**: 2026-05-10 — reflects all Dependabot alerts from the attached security report

## Vulnerability Classes Mapped to Orbit

### 1. Command Injection (HIGHEST RISK)
**Affected surfaces**: `github_actions.go`, `wazuh.go`, `apps.go`

**Status**: ALL FIXED
- `github_actions.go:581` — replaced `bash -c` with `exec.Command` args + regex validation ✓
- `wazuh.go:937` — replaced `bash -c` with safe arg-based commands + ManagerIP regex validation ✓
- `apps.go:342` — `splitShellWords()` parser replaces `bash -c`; commands word-split and passed directly to `exec.Command`, eliminating shell interpreter injection ✓

### 2. Authentication Bypass (CRITICAL)
**Status**: MITIGATED
- `requireAuth` middleware applied to all sensitive routes ✓
- CSRF tokens enforced on mutation endpoints ✓
- Rate limiting (300 req/min/IP global + per-user on mutations) ✓
- Session revocation via DB ✓
- API token scopes enforced ✓

### 3. Path Traversal (HIGH)
**Status**: FIXED
- `backup.go` — `safeRoot` sandbox added ✓
- `filesystem.go` — `safeRoot` with `filepath.EvalSymlinks`, kernel virtual path blocking ✓
- ZIP/tar extraction — symlinks now rejected in both formats ✓

### 4. SQL Injection (HIGH)
**Status**: MITIGATED
- All queries use `database/sql` parameterized `?` placeholders ✓
- No `fmt.Sprintf` in SQL construction ✓
- All ORDER BY clauses are hardcoded ✓

### 5. Container Escape (HIGH)
**Status**: MITIGATED
- Docker socket mounted `:ro` ✓
- `--cap-drop=ALL`, `--security-opt=no-new-privileges:true` ✓
- `SYS_PTRACE` capability REMOVED from docker-compose.yml ✓
- NET_ADMIN retained only for firewall management (documented) ✓

### 6. WebSocket Hijacking (HIGH)
**Status**: FIXED
- All 4 WebSocket upgraders (`hub.go`, `metrics.go`, `firewall.go`, terminal) have strict Origin checking ✓

### 7. Timing Attacks (MEDIUM)
**Status**: FIXED
- `agent.go` — replaced `!=` comparison with `crypto/subtle.ConstantTimeCompare` ✓

### 8. Information Disclosure (MEDIUM)
**Status**: FIXED
- `agent.go` — token only returned on initial registration, not re-registration ✓

### 9. XSS / DOMPurify Vulnerabilities (MEDIUM)
**Status**: FIXED
- DOMPurify updated to 3.4.2 in all lock files (was 3.2.7 as a transitive dep of monaco-editor) ✓
- npm `overrides` + pnpm `overrides` force all consumers to ≥3.4.0 ✓
- CSP header: `default-src 'self'; script-src 'self'; connect-src 'self' ws: wss:; frame-ancestors 'none'` ✓

### 10. Frontend API Resilience
**Status**: FIXED
- **Profile page "API endpoint unavailable" error** — root cause: Vite dev proxy was returning HTML 200 on backend-down errors; `request()` threw a confusing content-type error
  - Vite proxy error handler now returns JSON 503 ✓
  - `request()` error message improved to "Service temporarily unavailable — the server may still be starting up." ✓
  - Profile `useQuery` retries 3× with 1.5s delay before showing an error ✓
  - TOTP `useQuery` retries 2× with 1.5s delay ✓

### 11. Backend Connectivity — App Boot (NEW)
**Status**: FIXED — `useSetupStatus` hook extracted and hardened
- **`App.tsx` had an infinite retry loop** with no cap, no loading UI, no error state — the app silently hung forever if the backend was permanently down
- **Extracted to `web/src/hooks/useSetupStatus.ts`**:
  - Configurable `maxRetries` (default: 20 = ~30 seconds) and `retryDelayMs` (default: 1500ms)
  - Returns typed `{ setupRequired, loading, error, retryCount, retry }` state
  - Cleanup via `cancelled` flag to prevent state updates after unmount
  - `retry()` is a stable memoized callback
  - `MAX_RETRIES` and `RETRY_DELAY_MS` exported as named constants for testing
- **App.tsx** now shows:
  - Loading indicator with attempt count during startup (`"Connecting to server… (attempt N of 20)"`)
  - Error panel with Retry button after max retries
  - Correct routing (setup/login/authenticated) when status resolves
- **12 unit tests** covering all hook states: success, retry, max-retry error, cleanup, malformed response, non-ok HTTP response, retry() stability, unmount safety

## Data Flow Analysis

### Critical Flow: SSH Terminal
```
User → WebSocket → hub.go → terminal.go → SSH connection → remote server
  auth: JWT token validated on upgrade
  input: terminal keystrokes forwarded to SSH session
  output: terminal output sent back via WebSocket
  risks: terminal escape sequences, session hijacking, MITM
  mitigations: WebSocket origin check (all 4 upgraders hardened), JWT auth, SSH host key verification
```

### Critical Flow: File Operations
```
User → API → filesystem.go → safeRoot() → OS file operations
  risks: path traversal, symlink attacks, kernel virtual filesystem access
  mitigations: safeRoot sandbox, EvalSymlinks, kernel path blocking, data dir restriction
```

### Critical Flow: Docker Management
```
User → API → containers.go → exec.Command("docker", ...) → Docker socket
  risks: container escape via runc CVEs, socket abuse
  mitigations: read-only socket, dropped capabilities, no-new-privileges, SYS_PTRACE removed
```

### Critical Flow: App Install
```
User → API → apps.go → splitShellWords() → exec.Command(argv[0], argv[1:]...)
  risks: shell injection via crafted InstallCommand strings
  mitigations: splitShellWords parser eliminates bash -c; commands passed directly as argv
```
