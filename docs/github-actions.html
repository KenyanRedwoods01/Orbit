GitHub Actions

Orbit ships four production-grade workflows covering CI, releases, documentation, and security scanning.

Workflows overview

on: push (all branches) · pull_request

ci.yml — Continuous Integration

Runs golangci-lint, Go tests (race detection + coverage), TypeScript type-check, Vite build, and uploads a smoke-test binary artifact.

on: push tag v*.*.*

release.yml — Release Pipeline

Runs GoReleaser to produce Linux binaries (amd64/arm64/armv7), .deb and .rpm packages, and a multi-arch Docker image pushed to ghcr.io/kenyanredwoods01/orbit.

on: push to main (docs/**)

pages.yml — GitHub Pages

Deploys the docs/ directory to GitHub Pages. No build step — the site is pure HTML/CSS.

on: push to main · schedule (weekly)

security.yml — Security Scan

Runs govulncheck for Go CVE scanning and CodeQL analysis for Go and JavaScript. Results appear in the GitHub Security tab.

Creating a release

bash
# Bump version, tag, push — release workflow fires automatically
git tag v1.2.0
git push origin v1.2.0

# GoReleaser produces:
#  orbit_linux_amd64.tar.gz
#  orbit_linux_arm64.tar.gz
#  orbit_linux_armv7.tar.gz
#  orbit_1.2.0_amd64.deb
#  orbit_1.2.0_x86_64.rpm
#  ghcr.io/kenyanredwoods01/orbit:v1.2.0
#  ghcr.io/kenyanredwoods01/orbit:latest
#  checksums.txt

Enabling GitHub Pages

  • Go to your repo → Settings → Pages
  • Source: GitHub Actions
  • The pages.yml workflow deploys on every push to main that touches docs/**
  • Site will be live at https://kenyanredwoods01.github.io/Orbit

Required permissions

The workflows use only GITHUB_TOKEN — no additional secrets needed. Make sure your repo has:

  • Actions → Workflow permissions: Read and write permissions
  • Pages: Source set to GitHub Actions
  • Packages: Enabled (for GHCR pushes on release)
