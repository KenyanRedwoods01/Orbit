Security Guide

Orbit is designed to be security-first. This guide covers the capability model, hardening checklist, and integrated security tools.

Capability model

Orbit runs as a dedicated orbit system user with only two Linux capabilities:

  • CAP_NET_ADMIN — required for reading and writing firewall rules via nftables/iptables
  • CAP_SYS_PTRACE — required for accurate per-process statistics via /proc/<pid>/maps

All other capabilities are dropped. NoNewPrivileges=yes prevents privilege escalation. ProtectSystem=strict makes the OS read-only except for explicitly listed paths.

Hardening checklist

  • Run behind a reverse proxy (Nginx) — never expose Orbit directly on port 80/443
  • Replace the auto-generated self-signed cert with a valid TLS certificate in production
  • Set a strong secret_key in orbit.toml (32+ random bytes)
  • Restrict panel access to a VPN or trusted IP range via firewall rules
  • Enable TOTP two-factor authentication in the panel Settings
  • Review the audit log regularly (Security → Audit Log)
  • Keep Orbit updated — run bash scripts/install.sh --version latest
  • Enable CrowdSec for community threat intelligence
Port exposure: All Orbit ports must be in the range 5000–6000. Do not expose these ports to the public internet without a firewall rule restricting access to trusted IPs.

Integrated security modules

Wazuh

SIEM and host-based intrusion detection. Managed from Security → Wazuh.

Suricata

Network intrusion detection system. Managed from Security → Suricata.

CrowdSec

Community-driven threat intelligence and IP blocking.

Fail2ban

Automatic IP banning for brute-force attempts.

Reporting a vulnerability

Please report security issues privately via GitHub's Security Advisories page. Do not file public issues for security vulnerabilities.
